# Filecoin Docs Linear Tracker Template

Use this structure for local tracker files and for Linear descriptions when the
user approves external writes. Keep sections that apply and delete sections that
do not.

```markdown

Local issue draft only. Do not post this to Linear or GitHub unless explicitly
requested.

Repository policy: use `https://github.com/filecoin-project/filecoin-docs` as
the authoritative upstream repository. Base implementation branches on
`filecoin-project/main`; if a branch is pushed to a fork, open PRs against
`filecoin-project/filecoin-docs:main`.

Validation policy: use scripts available on the current target branch. Run
focused Markdown lint for touched docs files when available, `npm run build`,
and link/redirect validation when those commands exist on the target branch or
the user explicitly accepts fork tooling.

## Branch And PR Policy

- [ ] Work happens on a topic branch based on `filecoin-project/main`.
- [ ] Branch name starts with `mikers/` and contains no `codex`, `chatgpt`,
  `openai`, standalone `ai`, `agent`, `bot`, or generated-work marker.
- [ ] Direct pushes to `main` are avoided unless explicitly authorized.
- [ ] PRs target `filecoin-project/filecoin-docs:main`.
- [ ] PR body includes Linear links, scope, validation, and risks.
- [ ] PR title/body, commit text, and Linear text use neutral maintainer
  language and contain no tool/provenance markers unless explicitly approved.
- [ ] Latest-head checks are used as mergeability evidence.
- [ ] Review requests happen only after the PR is coherent and validated.

## Required PR Body Sections

- [ ] Summary
- [ ] Linear tracker links
- [ ] Files/sections changed
- [ ] Validation evidence
- [ ] Known risks or follow-ups
- [ ] Review/check status

## Public Output Hygiene

- [ ] Branch: `mikers/<issue>-<short-topic>-upstream-main`.
- [ ] Commit subject/body are task-focused and contain no AI/tool provenance.
- [ ] PR title/body/comments contain no `Codex`, `ChatGPT`, `OpenAI`,
  `AI-generated`, `generated by`, `agent`, `bot`, or similar markers.
- [ ] Linear title/description/comments contain no AI/tool provenance markers.
- [ ] No tool identity appears in `Co-authored-by` trailers.

## Milestones

### M0. Inventory And Mapping

- [ ] Confirm current upstream branch and file paths.
- [ ] Confirm relevant production URLs and redirects.
- [ ] Confirm current Linear state and parent/child links.

### M1. Draft Or Implement

- [ ] Make the smallest coherent docs/navigation change.
- [ ] Preserve stable URLs unless redirects are handled.
- [ ] Keep moved/deleted content accounted for.

### M2. Validate

- [ ] Run focused Markdown lint for touched files when available.
- [ ] Run `npm run build`.
- [ ] Run link/redirect checks when available on the target branch.
- [ ] Inspect PR checks after opening a PR.

### M3. Linear And PR Handoff

- [ ] Update local tracker with PR URL and validation evidence.
- [ ] Comment Linear with branch/base, PR URL, scope, and validation.
- [ ] Move Linear state to `In Review` when the PR is ready for review.
- [ ] Move Linear state to `Done` only after merge or explicit acceptance.

## Completion Criteria

- [ ] Target docs/navigation behavior is present.
- [ ] Links and redirects are valid or compatibility is documented.
- [ ] Changed pages are listed in `SUMMARY.md` when required.
- [ ] PR is open/merged according to the requested stop point.
- [ ] Linear has final evidence and state.
```

## Drafting Rules

- Use checkboxes as a work log.
- Keep current evidence, target state, and completion criteria separate.
- Keep tracker text suitable to copy into Linear or PR bodies without exposing
  tool/provenance markers.
- Do not claim a validation command passed unless it was run or a current GitHub
  check proves it.
- Prefer exact dates over relative dates.
- For umbrella trackers, create a parent sequencing issue and child execution
  issues, and cross-link both directions.
- For docs-only work, performance sections are usually unnecessary. If a change
  touches scripts, builds, generated output, or runtime assets, include a
  material-regression gate and before/after evidence.
